# 对对碰 · 规则与数值明细

这份文档记录**每一条规则的来源**，以及所有可调数值的含义，方便日后对照原版继续校准。

## 规则来源

| 规则 | 依据 |
|---|---|
| 点击上下左右相连、≥2 个同色方块整组消除 | 用户提供的原版玩法清单 |
| 斜向不算相连，单块点不掉 | 同上 |
| 消除后上方方块落下填补 | **原版录屏逐帧解析**：把棋盘解成占位矩阵后，每一列都严格底对齐，且消除一格后该列上方整体下移一行 |
| 整列清空后右侧列左移 | SameGame 的标准行为；录屏时长内未出现空列，属于合理推断 |
| 魔术方块点击换色、可任意配 | 用户说明 + 录屏中该方块（绿色小人）不计入顶部颜色计数条 |
| 第 1 关目标 1000 分 | 录屏中「过关目标分数」显示 1000 |
| 消 2 个 = 20 分 | 录屏中连续两次消 2 个，分数 300→320→340 |
| 道具为「删除」「变换」各 3 个 | 录屏右侧面板 |
| 5 种方块 | 录屏顶部计数条恰好 5 格，且计数之和 + 魔术方块数 = 棋盘方块总数 |
| 游戏任务（第 6 关起） | 用户提供的玩法清单 + 录屏中的「游戏任务」面板 |
| 剩余越少奖励越高 | 用户提供的玩法清单 |

> 未能核实的部分（三个官方规则页与 B 站视频在开发环境里都被网络策略拦截）已按 SameGame 的通行做法实现，并在此标注。

## 计分

```
单组得分 = groupFactor × colorFactor[颜色数] × n × (n − 1)
```

`groupFactor = 10`，5 色时 `colorFactor = 1.0`，于是：

| 一次消除 | 得分 | 相当于 |
|---|---|---|
| 2 个 | 20 | 基准 |
| 3 个 | 60 | 3 次两连 |
| 4 个 | 120 | 6 次两连 |
| 6 个 | 300 | 15 次两连 |
| 8 个 | 560 | 28 次两连 |
| 10 个 | 900 | 45 次两连 |
| 15 个 | 2100 | 105 次两连 |

额外：

- 一次消除 ≥ 8 个：每多 1 个再加 150 分
- 消到魔术方块：每个 +80 分
- 全盘清空：+2000 分
- 剩余方块奖励：`max(0, 900 − 剩余数 × 25)`
- 完成一个任务：+800 分
- 提示扣 30 分，变换扣 80 分，删除不扣分也不得分

## 目标分

固定大小的棋盘总分是有上限的，目标分硬涨只会变成必输。所以：

```
目标分 = 该配置下「认真玩能拿到的分」× 难度压强
```

- **可达分**由 `tools/curve.mjs` 实测标定的「单格期望产出分」乘以格数得出，再按魔术方块（加成）和顽石（惩罚）修正
- **难度压强**从第 1 关的 22% 一路爬到 90%
- 最后强制**单调不降** —— 宁可微微超过软上限，也不能让玩家看到目标分往回掉

结果：第 1 关 1000 分，第 10 关 4100，第 20 关 6950，第 30 关后稳定在 7350 左右。

## 难度推进

原版从头到尾就是 5 种方块，所以难度**不靠加颜色**，而是：

- 每 5 关棋盘长高一行（10×10 → 10×14）
- 第 3 关起出现魔术方块，比例从 2.5% 涨到 7%
- 第 12 关起出现顽石，比例从 1.5% 缓慢涨到 4.2%（涨得很慢，否则会拉低分数天花板导致目标分倒退）
- 第 6 关起出现任务目标
- 难度压强持续上升

## 可调项

所有数值集中在 `src/core/config.js`，改完跑 `npm run balance` 就能看到难度曲线是否被破坏。

| 常量 | 含义 |
|---|---|
| `SCORE.groupFactor` | 单组得分系数 |
| `SCORE.colorFactor` | 颜色数补偿系数，让分数尺度不随颜色数崩塌 |
| `STAGE.pressureBase/Step/Max` | 难度压强曲线 |
| `STAGE.hardCap` | 目标分相对可达分的软上限 |
| `STAGE.rowEveryStages` / `maxExtraRows` | 棋盘长高的节奏 |
| `STAGE.magicRate*` / `stoneRate*` | 特殊方块比例 |
| `BOARD_PRESETS` | 棋盘尺寸预设 |
| `COLLAPSE` | 填补方式（默认 `gravity` 为原版；另有向中间靠拢等变体） |
